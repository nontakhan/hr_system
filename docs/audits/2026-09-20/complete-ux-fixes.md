# ผลแก้รายการคงเหลือจาก UX audit

วันที่ 20 กันยายน 2026 · ฐานโค้ด `82825b2` บน `main`

ผู้ใช้อนุมัติให้แก้รายการที่เหลือทั้งหมดต่อจากรอบเร่งด่วน โดยคง PHP/Bootstrap/Sarabun และสิทธิ์ HR ที่จัดการบัญชี employee ได้เฉพาะในขอบเขตตนเอง ผลนี้เป็นการแก้และทดสอบใน local/fixture ยังไม่ได้ deploy production

## สถานะตามรายงานเดิม

| ประเด็น | สิ่งที่แก้และตรวจแล้ว |
|---|---|
| รายละเอียดก่อนอนุมัติ | แถวมี “ดูรายละเอียดคำขอ”; กล่องเดิมมีชื่อเต็ม เลขคำขอ ประเภท วัน/ช่วงวัน จำนวนหรือเวลา เหตุผลเต็ม และเอกสารแนบ ครอบคลุมลา/เวลา/OT/สลับวัน/กิจกรรม |
| การตัดสินใจและกดซ้ำ | ปุ่ม “ไม่อนุมัติ” ชัดเจน ข้อความอนุมัติยกเลิกตรงสถานะ ป้องกันส่งซ้ำ คืนปุ่มเมื่อ API ผิดพลาด และเก็บเหตุผลร่างแยกคำขอ ตรวจเหตุผลปฏิเสธฝั่ง server เพิ่มด้วย |
| การใช้งานคีย์บอร์ด | Sidebar มีชื่อ/expanded/controls, ปิดด้วย Escape/ปุ่มปิด/พื้นหลังและคืน focus; เมนูซ่อนใช้ inert, มือถือจำกัด focus ภายในเมนู และข้าม breakpoint แล้วสถานะตรงภาพ |
| Labels/วันที่/พื้นที่กด | ผูก for/id ในแบบฟอร์มคำขอ พนักงาน ตัวกรอง และกล่องยืนยัน; ปุ่มรหัสผ่าน 44px; ปฏิทินมีชื่อเดือน/วันไทยและไม่ล้นขวา; focus ชัดและรองรับ reduced motion |
| Login มือถือ/contrast | ย่อหน้าแนะนำให้เหลือชื่อองค์กรและหน้าที่ระบบ ฟอร์มอยู่ต้นหน้า ลด padding/ตกแต่ง เพิ่ม contrast และเรียง h1/h2 ถูกต้อง; ปุ่มเข้าสู่ระบบอยู่ในจอ 320 และ 390px |
| เมนู HR/Admin | แยกเวลาทำงานของฉันจาก `attendance.php?view=team`; ย้าย proxy ไปงานฝ่ายบุคคล; แบ่งงานประจำ/ตั้งค่าใน submenu เดิม; แก้ลิงก์กลับจากงาน HR ให้ตรงบริบท |
| บัญชีและสิทธิ์ | ทางลัดจากข้อมูลพนักงานไปส่วนบัญชีในฟอร์มเดิม พร้อมคำอธิบายสิทธิ์; HR ที่แก้บัญชีระดับสูงไม่ได้ไปถึงข้อความอธิบายแทนจุดว่าง |
| หน้าแรกตามบทบาท | หัวหน้า/HR/admin เห็นคิวอนุมัติที่ใช้จำนวนจริงตาม scope ก่อนสถิติองค์กร; บัญชีที่เชื่อมพนักงานมีทางเข้าประวัติคำขอครบทุกประเภท |
| ทำรายการแทนพนักงาน | แสดงคน/หน่วยงานปัจจุบัน เลือกจากทางลัดได้เฉพาะคนในผล API ที่มีสิทธิ์; confirmation แสดงเฉพาะช่องที่ใช้งานและวันที่ไทย พร้อมผล “บันทึกและอนุมัติทันที”; กลับไปแก้ไขแล้วข้อมูลยังอยู่ |
| ตารางหลังทำรายการ | Refresh เงื่อนไขเดิมคงหน้า/ค้นหา/เรียง; เปลี่ยนตัวกรองกลับหน้าแรก; แถวสุดท้ายในหน้าท้ายหายแล้วถอยหน้าที่มีข้อมูล; โหลดผิดพลาดมีลองใหม่ |
| รายงาน | แสดง snapshot ตัวกรองของผลล่าสุดทั้ง 4 รายงาน จับค่าก่อนรอ API และกัน response เก่าทับผลใหม่; แก้ filter ยังต้องกดแสดงรายงานตามเดิม; ออกใบเตือนแล้วคงหน้า/ค้นหา/เรียงของผลเดิม |
| คำศัพท์ | ปรับ Actions, User Account, Role และ label ที่เกี่ยวข้องเป็นภาษาไทย โดยไม่เปลี่ยน enum/API keys |
| “จดจำฉันไว้” | เอาตัวเลือกที่ไม่มีผลออก ไม่เพิ่มระบบ persistent login หรือเก็บข้อมูลรับรองตัวตน |
| การถอนใบลารอ HR | คงกติกาเดิมระหว่างยังไม่มีคำตอบเปลี่ยนนโยบาย: แจ้งให้ติดต่อ HR หากต้องการถอน; UI และ API สอดคล้องกัน เพิ่มเงื่อนไขเจ้าของ/สถานะเดิมและ affected_rows กันการถอนชนกับการอนุมัติ; approved ยังต้องขอ HR อนุมัติยกเลิก |
| เอกสารแนบส่วนบุคคล | เพิ่ม `attachment.php` ตรวจบัญชี/role/scope ปัจจุบันจาก DB และผูกเอกสารกับเจ้าของจริง; ปิด static URL สองโฟลเดอร์; เก็บ path และไฟล์เดิม รองรับหลายไฟล์ต่อใบลาโดยไม่สร้างแถวอนุมัติซ้ำ |

## ขอบเขตเอกสารแนบ

- เจ้าของคำขอและหัวหน้าปัจจุบันอ่านเอกสารคำขอที่เกี่ยวข้องได้; HR ใช้ company หรือ branch scope; admin อ่านได้ทั้งระบบ
- เอกสารในประวัติบุคลากรใช้สิทธิ์ HR/admin ตามหน้าจัดการประวัติเดิม ไม่มีการขยายสิทธิ์ management ให้ employee/manager
- รับชนิดและ ID ของรายการ ไม่รับ filesystem path จากผู้ใช้ ตรวจ realpath ให้อยู่ในโฟลเดอร์ที่อนุญาต ตรวจ MIME และส่ง no-store/nosniff
- URL เดิมใต้ `assets/uploads/leaves/` และ `assets/uploads/employee_training/` ถูกปิดด้วย `.htaccess`; ลิงก์ใหม่ตรวจสิทธิ์ทุกครั้ง รูปโปรไฟล์เป็นคนละโฟลเดอร์
- เงื่อนไขนี้ต้องติดตั้งทั้ง endpoint, frontend และ `.htaccess` พร้อมกัน และยืนยันกฎปิด static URL บนเว็บเซิร์ฟเวอร์ปลายทางก่อนรับรอง production

## Browser และ HTTP

Chromium ผ่าน Playwright กับ PHP fixture server และข้อมูลสังเคราะห์:

- Login 320/390/1365px: ปุ่มอยู่ใน viewport, ปุ่มรหัสผ่านกว้าง 44px, failed login คืนปุ่มและเก็บ username, keyboard/help ใช้ได้
- ฟอร์มลา/เวลา/OT/สลับวัน/กิจกรรม, proxy ทุกแท็บ, เพิ่ม/แก้พนักงาน: ไม่มี visible control ที่ขาด label หรือ id ซ้ำในหน้าที่ตรวจ; ไม่มี document horizontal overflow ที่ 320/390px
- เมนูมือถือปิดด้วยปุ่ม X และ Escape, คืน focus, Tab ไม่เข้าเมนูที่ซ่อน และ resize 390→1365→390 สอดคล้องกับ aria-expanded
- Manager ส่ง submit event สองครั้งเกิด POST ครั้งเดียว; API error คืนปุ่มและคงเหตุผล; ปิด/เปิดกล่องแล้วเหตุผลยังอยู่
- อนุมัติจริงบน fixture จนหน้าท้ายหมด: ตารางกลับไปหน้าที่มีข้อมูล; กล่องอนุมัติมือถือเลื่อนรายละเอียดภายในและคงปุ่มตัดสินใจในจอ
- กล่องคำขอยกเลิกกิจกรรมและสลับวันสื่อ “ยกเลิก” ตรงกัน; proxy ยกเลิก confirmation แล้วข้อความที่กรอกยังอยู่
- รายงานทั้งสี่แสดง applied filters ตรงผล; เปลี่ยนเดือนโดยยังไม่กดแสดงรายงานไม่เปลี่ยนป้ายของผลเดิม
- ถอนใบลารอหัวหน้าสำเร็จ, เหตุผลว่าง/ถอนซ้ำ/ถอนช่วงรอ HR ถูกปฏิเสธตามกติกาเดิม
- Apache localhost: ไฟล์ PDF จำลอง static URL ได้ HTTP 200 ก่อนแก้ → 403 หลังแก้; URL guest ผ่าน endpoint ได้ 403; เจ้าของผ่าน endpoint บน fixture ได้ PDF HTTP 200
- Integration ครอบคลุม owner/manager/admin, HR company/branch/ไม่มี scope, revoke role/scope, path traversal, file ID ที่ไม่สัมพันธ์กับคำขอ, ประวัติบุคลากร และหลายเอกสารต่อใบลา

## ข้อจำกัดของผล

การแก้ในโค้ดตามรายงานเสร็จพร้อมหลักฐาน local/fixture แต่ยังไม่ใช่ usability test กับผู้ใช้จริง, การรับรอง WCAG ทั้งระบบ หรือ production acceptance ทุกบทบาท คะแนน 21/40 ในรายงานเดิมเป็นผลก่อนแก้ ไม่ได้แทนที่ด้วยคะแนนใหม่จากผล automated tests

ไม่มี migration ใหม่ ไม่มีการ deploy หรือแก้ฐานข้อมูล production การเปลี่ยนนโยบายถอนใบลาระหว่างรอ HR และการเพิ่ม persistent login ต้องเป็นงานที่กำหนดกติกาต่อหากต้องการเปลี่ยนจากแนวทางที่ใช้รอบนี้
